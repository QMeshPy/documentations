## 🎯 CORE THESIS & KEY POINTS

### **One-Sentence Thesis**
"AI agents should join networks as first-class peers, not call APIs as clients."

### **The 4 Proof Points**

**1. Economic Agency** (Basescan)
- Agents have wallets via Coinbase AgentKit
- Autonomously transfer USDC on Base L2
- Verifiable on blockchain (no mock payments)

**2. Peer Coordination** (libp2p)
- Discovery via DHT (no registry)
- Notifications via GossipSub (no REST polling)
- Execution via multiplexed streams (no API gateway)

**3. Verifiable Storage** (IPFS)
- Content-addressed via CIDs
- Cryptographic hash verification
- No trust required (just verify the hash)

**4. Autonomous Intelligence** (Claude 3.5)
- Analyzes proposals (AWS Bedrock)
- Makes funding decisions
- Executes without human approval

### **Closing Line** (Memorize)

<a name="qa-preparation"></a>
## 💬 Q&A PREPARATION

### **Expected Question 1**

**Q**: *"How is this different from Ray or Dask for distributed computing?"*

**A**: 
```
"Ray and Dask assume a trusted coordinator and shared filesystem. 
Our workers are untrusted peers who can join freely. libp2p handles 
discovery without registry. IPFS handles content-addressed results 
without shared disk. Blockchain handles payments without escrow trust. 
Agents verify everything cryptographically—they trust the math, not 
the platform."
```

---

### **Expected Question 2**

**Q**: *"Why blockchain? Seems like overkill."*

**A**: 
```
"Two reasons: First, agents need wallets to autonomously pay for 
resources. Blockchain enables this without platform custody. Second, 
payment history is public and immutable—creates a reputation system 
where workers are incentivized to be reliable. We're using Base L2, 
so transactions are instant (2-second finality) and essentially free 
for USDC."
```

---

### **Expected Question 3**

**Q**: *"Can't you just use AWS S3 + DynamoDB?"*

**A**: 
```
"You could, but agents would have to trust AWS isn't tampering. With 
IPFS + CIDs, verification is cryptographic. Agents prove data integrity 
without trusting storage provider. This enables composability: Agent A 
stores, Agent B verifies, Agent C builds on top—all without coordinating 
permissions through a central platform. Trust the hash, not the host."
```

---

### **Expected Question 4**

**Q**: *"What if a worker lies about results?"*

**A**: 
```
"Good question. Right now, we assume honest workers—this is a research 
platform. For production, three approaches: (1) Redundant execution—3 
workers compute, majority wins. (2) Zero-knowledge proofs—worker proves 
correct execution without revealing state. (3) Optimistic rollups—assume 
honest, slash stake if caught. We're exploring #1 and #3. The blockchain 
infrastructure is already there—just need verification protocol."
```

---

### **Expected Question 5**

**Q**: *"How does this scale?"*

**A**: 
```
"By component: libp2p DHT scales to millions (IPFS proves this). GossipSub 
scales to thousands per topic. Base L2 handles 50k+ TPS. MongoDB shards 
horizontally. Bottleneck right now is AWS Bedrock API rate limits—about 
100 analyses/minute. Solutions: multi-region endpoints, request queueing, 
or local models for simple decisions. But for a research platform, we're 
nowhere near these limits."
```

---

### **Expected Question 6**

**Q**: *"What about privacy? IPFS is public."*

**A**: 
```
"Correct—IPFS is public, fine for open science. For private data: 
(1) Encrypt before upload, agents share keys via libp2p encrypted streams. 
CID is public, content is encrypted. (2) Private IPFS swarm—permissioned 
network. (3) Filecoin with encrypted storage deals. These are composable—
mix public and private depending on research type. Infrastructure stays 
the same, add encryption at application layer."
```

---

### **Expected Question 7**

**Q**: *"Is the quantum computing part real?"*

**A**: 
```
"It's simulated—Qiskit's statevector simulator, not real quantum hardware. 
Real hardware (IBM Q, IonQ) is expensive, has wait queues, and introduces 
noise that complicates demos. But the orchestration is real. The peer-to-peer 
coordination is real. The same infrastructure could orchestrate IBM's quantum 
computers, TPUs for AI training, or GPUs for rendering. The contribution here 
is composable infrastructure for agentic coordination, not the quantum physics."
```
